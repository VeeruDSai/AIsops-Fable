## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (button icon↔label gap) |
| md | 16px | Default element spacing; reader canvas padding on mobile (`p-4`) |
| lg | 24px | Section padding; reader canvas padding at ≥640px (`sm:p-6`); layout gaps |
| xl | 32px | Layout gaps between reader canvas and form column |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- Reader action buttons (`Copy Story`, `Print / Save PDF`) reuse the established control padding `px-4 py-2.5` = **16px horizontal / 10px vertical** from `StoryForm.tsx` for visual consistency. The 10px vertical pad is the sole sub-8-grid value carried into this phase.
- Accessibility override: every reader action button must still present a **≥44px tall hit target** (WCAG 2.5.8) regardless of the 10px visual padding.
- Reader prose measure is capped at **65ch (~680px)** (Tailwind Typography default max-width) for comfortable book-like reading; this is a content measure, not a spacing token.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (story prose) | 17px | 400 (regular) | 1.7 |
| Label (reader chrome / action buttons) | 14px | 600 (semibold) | 1.4 |
| Heading (`###` narrative stages) | 24px | 600 (semibold) | 1.25 |
| Display (`#` story title) | 32px | 600 (semibold) | 1.2 |

- Exactly **2 weights**: regular 400 (prose body) and semibold 600 (labels, headings, display). No other font weights in this phase.
- Body line-height 1.7 and heading line-height 1.2 are deliberate for a book-like reading cadence (1.7 for generous serif reading; heading values track the recommended 1.2).
- Apply as: `prose prose-stone font-serif` on the reader container, overriding body to 17px/1.7, `h1` to 32px/600/1.2, and `h3` to 24px/600/1.25 via `prose-*` modifiers or a small `@theme`/CSS override in `globals.css`.
- The live-region text node keeps `font-serif` and `leading-relaxed` (existing pattern) until prose classes take over once markdown renders.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Copy Story |
| Secondary action | Print / Save PDF |
| Empty state heading | Your Story *(reader section label; preserves the "Story preview" section-heading role)* |
| Empty state body | Your tale will appear here as it is written. |
| Loading indicator | Writing… *(with spinning `LoaderCircle` icon — existing pattern)* |
| Error state (connection) | Could not reach the storyteller. Check your connection and try again. |
| Error state (rate limit) | Rate limit reached — the storyteller needs a short breather. Please wait a moment and try again. |
| Copy confirmation | Copied! |
| Destructive confirmation | N/A — no destructive actions in this phase |

- Error copy is **verbatim** from `src/hooks/useStoryGeneration.ts` (`CONNECTION_MESSAGE`, `RATE_LIMIT_MESSAGE`); server-supplied messages pass through unchanged. Do not invent new error strings in the reader.
- "Copied!" appears immediately on successful `navigator.clipboard.writeText` and auto-reverts to "Copy Story" after **2000ms** (defined default for "a brief/short delay"). On clipboard rejection, keep the idle label — never show a false "Copied!".

**Interaction contract (locked by `04-CONTEXT.md` — executor source of truth):**
- **Markdown heading mapping:** render `# Title` as the story title (h1). Render `### Beginning`, `### Middle`, `### Climax`, `### Resolution` as narrative stage headings (h3). Treat `### Conclusion` as an equivalent to `### Resolution` — both are the final section with no visual distinction.
- **Copy Story:** `navigator.clipboard.writeText(rawStoryText)` — copies the **raw markdown source string**, not the rendered DOM text. Show "Copied!" confirmation, auto-revert after 2000ms.
- **Print / Save PDF:** `window.print()`. `@media print` hides the configuration form and **all reader controls** (Copy/Print buttons, "Writing…" indicator, section labels, error alerts) so only the story content prints. Print layout uses the same serif prose with black-on-white text, no shadows/borders, and a constrained reading measure. (Print is an open/domain-owned concern per the probe boundary — covered by CSS rules here, not forced into the closed taxonomy.)
- **Accessibility:** retain polite live-region behavior for streamed text (`aria-live="polite"`, `aria-atomic="false"`); reader action buttons have accessible names/labels and visible focus rings; icons are `aria-hidden="true"`.
- **Scope fence:** no regeneration, Surprise Me, API/model changes, authentication, persistence, or deployment in this phase (those are Phase 5 / out of scope).
