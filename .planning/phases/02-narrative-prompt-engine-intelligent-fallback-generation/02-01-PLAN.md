    Create `src/lib/prompts.ts` exporting:
    1. `STORY_SYSTEM_INSTRUCTION`: Comprehensive instructions directing Gemini to act as a master storytelling bard. Enforces:
       - Classical 4-part structure formatted in Markdown: `# [Catchy Title]`, `### The Beginning`, `### The Middle`, `### The Climax`, `### The Conclusion`.
       - High prose quality: vivid imagery, natural dialogue, emotional resonance, and clear theme/moral.
       - Markdown formatting only (no meta-chatter, no preamble like "Here is your story:", no conversational wrap-up).
    2. `buildStoryPrompt(request: StoryRequest): string`:
       - Sanitizes and truncates character names (max 50 chars), roles (max 100 chars), and premise (max 500 chars).
       - Encloses user inputs within `<user_inputs>` boundary tags to prevent prompt injection or format derailment.
       - Implements intelligent fallback logic:
         - If characters are provided: lists them with names and roles. If missing: instructs the model to invent 1-2 compelling characters suited to the tale.
         - If genre is provided: frames the tone, tropes, and atmosphere. If missing: instructs the model to select an imaginative genre organically.
         - If premise is provided: incorporates the hook/conflict. If missing: instructs the model to create an unexpected, captivating inciting incident.
         - If request is completely empty (`{}`) or has `isSurprise: true`: explicitly prompts for an unexpected, eccentric, delightful fable.
    Create `tests/prompts.test.ts` covering:
    - Full inputs (characters + genre + premise) incorporated correctly.
    - Partial inputs (only character, only genre, or only premise) activate intelligent fallback directives.
    - Empty input `{}` activates full creative autonomy fallback.
    - Prompt injection attempts (e.g., "Ignore previous instructions") remain contained in `<user_inputs>` and treated strictly as narrative fiction ingredients.
    - Output prompts always mandate the 4-part structure headers.
    Run `npx vitest run tests/prompts.test.ts`.

<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| Client Form Input → Server Prompt Builder | Unsanitized user inputs could contain malicious instructions or huge strings aimed at prompt injection or buffer bloat |
| Server Prompt Builder → Google Gemini API | Prompt structure must constrain model output to markdown story text, suppressing conversational tangents |

## STRIDE Threat Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | Prompt Builder (`src/lib/prompts.ts`) | high | mitigate | Wrap user inputs inside `<user_inputs>` boundary tags and instruct the model that content inside these tags is purely fictional creative material |
| T-02-02 | Denial of Service | Input Validation (`src/lib/prompts.ts`) | medium | mitigate | Defensively cap string lengths: character name <= 50, role <= 100, premise <= 500 characters |
| T-02-03 | Tampering | Output Structure | medium | mitigate | Enforce strict markdown formatting contracts (`# Title`, `### The Beginning`, etc.) and prohibit meta-chatter |
</threat_model>
